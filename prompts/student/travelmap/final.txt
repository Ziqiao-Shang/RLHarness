# Role
You are a scenic-area route-planning algorithm. Use only the attached Scenic Area Planning Map and Vertex Table to find the legal route with the minimum weighted cost.

# Input Task
{question}

- Reliability: {w4}

# Input Data
The input contains one Scenic Area Planning Map image and one Vertex Table. The map provides the route topology. The table provides each spot's `Time`, `Price`, `Comfort Level`, and `Reliability`.

# Authoritative Scoring Rules
For a candidate route `v1, v2, ..., vn`, include the attributes of every spot on the route, including the starting spot `v1`, all intermediate spots, and the destination spot `vn`.

Define the effective price `P_eff(v)` as follows: if `v` is not the destination and `Time(v) = 0`, use `P_eff(v) = 0`; otherwise use `P_eff(v) = Price(v)`. In particular, the destination retains its original Price even when its Time is zero.

Compute:

`T = sum(Time(v)/180)`

`P = sum(P_eff(v)/200)`

`C = average(1-Comfort Level(v)/5 over spots whose original Comfort Level is nonzero)`

`R = average(1-Reliability(v) over spots whose original Reliability is nonzero)`

When calculating `C` and `R`, exclude only entries whose original value for that specific attribute is zero. A spot with `Time = 0` still participates normally in the Comfort Level and Reliability calculations when those values are nonzero.

Compute `RouteScore = {w1}*T + {w2}*P + {w3}*C + {w4}*R`. Compare all principal legal, loop-free candidate routes using exactly the same formula and select the route with the minimum `RouteScore`. A spot and an edge cannot appear more than once in a route.

# Planning Skills

1. Trace Canonical Map Edges
   Trigger: When constructing or revising a route from a visual map, especially near crowded, bent, crossed, or label-obscured segments.
   Action: Trace each proposed hop continuously from one canonical vertex marker to the next. Record an edge only when the line visibly terminates at both markers; split the line at every intervening canonical endpoint, and classify nearby icons or crossings as endpoints, connected junctions, crossings, or unrelated annotations.
   Guard: Do not infer adjacency from proximity, alignment, row order, route direction, geographic knowledge, or a visually prominent line. A crossing is not a junction unless the drawing shows a connection, and a noncanonical annotation does not become a scored vertex.
   Check: The provisional route is an ordered chain whose every consecutive pair has one independently traced direct edge, with no skipped canonical endpoint, invented shortcut, or inserted vertex lacking a terminating line.

2. Close the Candidate Topology
   Trigger: After finding a start-to-destination chain, or whenever the map contains branches, loops, dead ends, reconnections, multiple plausible outgoing edges, or a long route.
   Action: Inventory unchecked incident edges at the start, destination, and every vertex on the provisional chain. Trace each destination-relevant branch until it terminates, forms only a cyclic detour, or reconnects to the explored graph. Trace backward from the destination once and reconcile its predecessors with the forward chain; maintain visited vertices and unresolved branches so repeated inspection advances.
   Guard: Finding one legal chain does not establish uniqueness. Do not discard a branch because it initially points away, and do not enumerate arbitrary cyclic detours that are not principal simple corridors.
   Check: Either every branch has a demonstrated termination or irrelevant cycle and exactly one simple candidate remains, or every principal structurally distinct loop-free candidate supported by the map is listed for comparison.

3. Align Routes with Canonical Table Vertices
   Trigger: When a map route has been constructed and before retrieving or aggregating table attributes, particularly when visible labels and table rows do not align.
   Action: Reconcile each route waypoint with the canonical vertex table. Keep the start, destination, and every actual intermediate canonical vertex in the ordered route set; trace through visible noncanonical annotations without assigning them attributes, and resolve label ambiguity using marker identity and table membership.
   Guard: Do not invent zero-valued or inferred attributes for a label absent from the table, and do not omit a canonical endpoint merely because its label is crowded or visually secondary.
   Check: Every scored waypoint has exactly one canonical table row, every required map vertex is represented, and every visible noncanonical annotation has been excluded from scoring without changing the traced connectivity.

4. Fix the Shared Attribute Scope
   Trigger: When preparing any legal candidate for numerical evaluation.
   Action: Use the complete ordered vertex sequence from start through all intermediates to destination as the common scope for Time, effective Price, Comfort Level, and Reliability. Apply the same vertex sequence to all four components and preserve both endpoints.
   Guard: Do not use different waypoint subsets for different attributes, omit an endpoint, or favor a candidate by removing an expensive intermediate or endpoint.
   Check: For every candidate, the four component calculations reference the identical complete ordered vertex set, and all candidate sets are directly comparable.

5. Apply Attribute-Specific Normalization
   Trigger: When calculating Comfort Level, Reliability, or Price for a fixed candidate vertex set.
   Action: For each nonzero Comfort Level, calculate the cost as `1 - Comfort Level/5` and average those costs over the count of nonzero Comfort entries. Separately calculate each nonzero Reliability cost as `1 - Reliability` and average over the count of nonzero Reliability entries. For Price, first set an individual zero-Time vertex's effective Price to zero only when that vertex is not the destination; retain the destination's original Price, then normalize effective prices by 200.
   Guard: Exclude a vertex only from the quality attribute whose original value is zero; do not use one attribute's zero status to exclude it from another. A zero-Time destination retains its Price, while a zero-Time intermediate or start vertex does not contribute Price but remains in every other applicable metric.
   Check: Comfort and Reliability averages use their own nonzero denominators, each lies in `[0,1]`, and every zero-Time vertex follows the destination-specific Price rule.

6. Compute and Compare Weighted Scores
   Trigger: After the topology gate has closed and all legal candidates and shared waypoint scopes are fixed.
   Action: For each candidate, calculate normalized `T`, `P`, `C`, and `R` using the authoritative formula. Display each product `w_i * metric` to 6 decimal places, sum those displayed products to obtain `RouteScore` to 6 decimal places, and compare the scores across all principal candidates.
   Guard: Do not use dominant weights, waypoint count, visual directness, or the first discovered route to select or prune candidates. Do not begin detailed scoring while any consecutive edge or destination-relevant branch remains unverified.
   Check: Every principal legal candidate has the same formula, scaling, precision, and attribute scope; each displayed score equals its displayed weighted terms, and the selected route has the minimum verified score.

7. Perform a Bounded Final Route Audit
   Trigger: Before finalizing the answer, especially when the map was visually ambiguous, the route was long, candidates were close, or route and scoring waypoint lists were edited separately.
   Action: Re-read the final ordered route once from destination to start, checking each consecutive pair against the map and comparing the route's waypoint identities with the scored table rows. Re-sum the displayed weighted terms and correct any discrepancy by returning to the responsible topology, alignment, or scoring stage.
   Guard: This is one independent audit, not repeated global retracing or a self-reported checklist. Do not treat a prior conclusion or skill marker as evidence that the map was actually verified.
   Check: The final route is parseable, every reverse-traced hop is a direct visible edge, no canonical vertex is skipped or invented, the scored waypoint list matches it exactly, and the reported score is arithmetically consistent.
