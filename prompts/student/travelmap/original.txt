# Input Data
The input contains one Scenic Area Planning Map image and one Vertex Table. The map provides the route topology. The table provides each spot's `Time`, `Price`, `Comfort Level`, and `Reliability`.

# Authoritative Scoring Rules
For a candidate route `v1, v2, ..., vn`, include the attributes of every spot on the route, including the starting spot `v1`, all intermediate spots, and the destination spot `vn`.

Define the effective price `P_eff(v)` as follows: if `v` is not the destination and `Time(v) = 0`, use `P_eff(v) = 0`; otherwise use `P_eff(v) = Price(v)`. In particular, the destination retains its original Price even when its Time is zero.

Compute:

`T = sum(Time(v)/180)`

`P = sum(P_eff(v)/200)`

`C = average(1-Comfort Level(v)/5 over spots whose original Comfort Level is nonzero)`

`R = average(1-Reliability(v) over spots whose original Reliability is nonzero)`

When calculating `C` and `R`, exclude only entries whose original value for that specific attribute is zero. A spot with `Time = 0` still participates normally in the Comfort Level and Reliability calculations when those values are nonzero.

Compute `RouteScore = {w1}*T + {w2}*P + {w3}*C + {w4}*R`. Compare all principal legal, loop-free candidate routes using exactly the same formula and select the route with the minimum `RouteScore`. A spot and an edge cannot appear more than once in a route.

# Planning Skills

1. Derive Topology from Map Edges
   When to apply: When identifying adjacency, reconstructing the local graph, or building candidate routes.
   Procedure: Determine connections edge by edge strictly from the continuous lines drawn in the map image. Travelmap graphs are undirected (bidirectional) networks of scenic routes; trace each drawn polyline from node endpoint to node endpoint rather than assuming spatial proximity, row order, or external geographic knowledge implies a connection.
   Check: Every consecutive pair of spots must be connected by one direct visible line segment on the map without skipping intermediate labeled icons or inventing imaginary shortcuts between degree-1 leaf nodes.

2. Expand Every Traversed Spot
   When to apply: When tracing a route through a chain, branch, intersection, bend, or visually dense region.
   Procedure: Follow the chosen through-path continuously from spot to spot and record every labeled spot on that through-path, ensuring intermediate nodes situated along the line (e.g. transit stations, landmarks) are included. At each junction, distinguish trunk through-corridors from terminal side branches/dead ends (degree-1 leaf nodes connected only to that junction); never treat a leaf node as a through-bridge or insert a dead-end spur unless it is the designated start or destination.
   Check: Do not skip a visible intermediate spot on the path, insert a dead-end spur that requires backtracking, reverse route order, or invent non-existent connections.

3. Normalize Spot Names
   When to apply: When the map and Vertex Table use aliases, abbreviations, translations, punctuation, or similar-looking names.
   Procedure: Use map position and neighboring spots to match each map node to exactly one canonical Vertex Table entry. Use that table name consistently in calculations and final output.
   Check: Never attach one spot's attributes to another spot or treat two spellings of the same spot as separate vertices.

4. Separate Map Topology from Table Attributes
   When to apply: Whenever determining adjacency and retrieving numerical attributes.
   Procedure: Use the map image only to establish direct connections and route order. Use the Vertex Table only to retrieve the four attributes after a spot has been identified.
   Check: Table row order does not imply map adjacency, and numerical similarity does not create an edge.

5. Enumerate Structurally Distinct Candidates
   When to apply: When branches, cycles, crossings, or multiple connecting corridors may provide different legal routes.
   Procedure: Construct the principal structurally distinct loop-free candidates supported by visible edges. Include alternatives that could plausibly change the weighted decision, but omit routes that are merely long cyclic detours.
   Check: Do not select the route solely because it has the fewest spots, looks most direct, or is the first route noticed.

6. Distinguish Unique and Multi-Path Topologies
   When to apply: After the initial topology inspection and before numerical scoring.
   Procedure: Determine whether exactly one legal simple route exists. If so, retain that route and state the concrete topological reason. If alternatives exist, compare the principal legal candidates.
   Check: Do not invent alternatives for a unique path or declare a route unique before checking visible branches and reconnections.

7. Compute Weighted Cost Consistently
   When to apply: After the legal candidate routes have been fixed.
   Procedure: For every candidate, compute `T`, `P`, `C`, and `R` to 6 decimal places with the authoritative formula. Show each individual weighted product term (`w_i * metric`) before summing them to obtain the final `RouteScore` (to 6 decimal places).
   Check: Use identical scaling, precision, and attribute scope for every candidate. Do not replace the formula with an informal preference or shortest-route heuristic.

8. Include Both Route Endpoints
   When to apply: When building the attribute list for a candidate route.
   Procedure: Include the start, every intermediate spot, and the destination in the Time, Price, Comfort Level, and Reliability calculations, subject only to the effective-price and nonzero-average rules.
   Check: Do not omit either endpoint or use a different spot set for different attributes.

9. Average Nonzero Quality Costs
   When to apply: When calculating Comfort Level and Reliability costs.
   Procedure: Normalize each nonzero Comfort Level using `Comfort Level/5`, convert it to `1-Comfort Level/5`, and average those costs. Separately convert each nonzero Reliability value to `1-Reliability` and average those costs.
   Check: Exclude an entry only when its original value for that same quality attribute is zero. Do not sum quality costs without dividing by the correct nonzero count.

10. Apply the Zero-Time Effective-Price Rule
    When to apply: Whenever any route spot has `Time = 0`.
    Procedure: Set Price to zero only when that zero-Time spot is not the destination. If the zero-Time spot is the destination, retain its original Price. Normalize the resulting effective prices by 200.
    Check: Do not erase the destination's Price, retain an intermediate transport hub's Price, or omit its other nonzero attributes.

11. Recheck Close Candidate Scores
    When to apply: When two candidates have close totals, when different components favor different routes, or when one weight dominates the objective.
    Procedure: Recompute the component sums, quality averages, effective prices, weighted products, and final addition for the competing candidates before deciding.
    Check: A dominant weight guides attention but does not replace the complete weighted calculation. Every ranking claim must cite numerical scores.

12. Validate Every Edge Before Scoring
    When to apply: Before admitting a candidate to numerical comparison.
    Procedure: Verify the requested start and destination, each consecutive map edge, every intermediate spot, and the absence of repeated spots or edges.
    Check: Reject candidates containing an invented edge, skipped spot, wrong endpoint, repeated spot, repeated edge, or loop.

13. Perform a Final Audit of the Best Candidate
    When to apply: After identifying the current minimum-score candidate.
    Procedure: Audit the complete route, its table lookups, effective-price decisions, averaging denominators, weighted score, and agreement between the reasoning and final route.
    Check: If any item fails, correct the calculation or choose another validated candidate before answering.

14. Output the Complete Canonical Route
    When to apply: Once the best legal route has been established.
    Procedure: Output the start, every intermediate spot, and the destination in travel order using canonical Vertex Table names joined by hyphens.
    Check: Do not omit spots, translate names, add explanations inside the route, or place spaces around separators.

15. Prioritize a Complete Response
    When to apply: When the route is known or the remaining output budget is limited.
    Procedure: Always finish one complete `<reasoning>...</reasoning>` block followed immediately by one complete `<response>...</response>` block. Compress secondary explanation before sacrificing the final route.
    Check: Never return a truncated route, an empty block, a missing closing tag, or extra text outside the two required blocks.
