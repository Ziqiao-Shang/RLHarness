# Input Data
The input contains one metro map image and one Vertex Table. The table provides each station's `Time`, `Price`, `Comfort Level`, `Reliability`, and `Transfer Time`.

# Authoritative Scoring Rules
For a candidate route `v1, v2, ..., vn`, include the attributes of the starting station `v1` and all intermediate stations `v2...v(n-1)`, but exclude every attribute of the destination station `vn`.

Let `N` be the number of included stations. Compute:

`T = sum(Time(v)/3) + sum(Transfer Time(v)/3 at actual line changes)`

`P = sum(Price(v)/1.5)`

`C = sum(1-Comfort Level(v))/N = 1-mean(Comfort Level(v))`

`R = sum(1-Reliability(v))/N = 1-mean(Reliability(v))`

All attribute values, including values equal to zero, participate normally in these calculations and averages.

Compute `RouteScore = {w1}*T + {w2}*P + {w3}*C + {w4}*R`. Add Transfer Time only when the route actually changes from one metro line to another at that station; passing through a multi-line station without changing lines does not incur a transfer cost. Compare all principal legal, loop-free candidate routes using exactly the same formula and select the route with the minimum `RouteScore`. A station cannot appear more than once in the route.

# Planning Skills

1. Derive Topology from Map Edges
   When to apply: When determining whether two stations are adjacent, reconstructing line topology, or building candidate routes.
   Procedure: Determine station adjacency edge by edge strictly from the rail tracks drawn in the map image. The map topology frequently differs from real-world transit networks; strictly follow the visible map connections rather than external memory, city knowledge, or table row order. Trace the track continuously: include every station drawn along that traversed segment and never insert intermediate stations not directly connected on that segment.
   Check: Every consecutive pair of stations in the route must be connected by a direct visible edge on the map image. Never skip a station drawn along the active path or insert an unverified intermediate station.
2. Expand Stations in the Travel Direction
   When to apply: When continuing along a line or expanding a path after transferring to another line, especially around branches, loops, endpoints, bends, or densely placed labels.
   Procedure: Visually trace the drawn rail track station-by-station on the map image in the direction of travel. Metro lines in these maps often have rearranged, added, or skipped stations compared to real-world networks; never recall line orders from memory or assume standard geographic order. Record every station marker physically traversed on the track until reaching the transfer station or destination.
   Check: The station sequence must strictly match the visual image track order. Do not skip intermediate stations drawn on the line, insert unvisited stations from real memory, or reverse travel order.
3. Normalize Station Names
   When to apply: When map labels and Vertex Table entries differ through aliases, abbreviations, bilingual labels, suffixes, romanization, or spelling.
   Procedure: Use map position, adjacent stations, and line information to match each map node uniquely to its canonical Vertex Table entry. Use that canonical name consistently in the route and when reading attributes.
   Check: Each route node must correspond to exactly one table entry. Do not split variants of one station into separate vertices, confuse similar station names, or attach attributes to the wrong station.
4. Separate Table Attributes from Map Adjacency
   When to apply: When reading station attributes, confirming line membership, or deciding whether a station can serve as a transfer point.
   Procedure: Use the Vertex Table to verify a station's unique entry, line set, and attributes, and use the map to verify direct adjacency and travel order. For a transfer, confirm that both the incoming and outgoing lines are listed for the same station entry.
   Check: A line field proves only line membership, not adjacency between two stations. Do not join disconnected map segments or transfer at a station that does not belong to both relevant lines.
5. Enumerate Structurally Distinct Candidates
   When to apply: When the map permits a direct route, different branches, opposite directions around a loop, or multiple transfer combinations between the start and destination.
   Procedure: List the structurally distinct candidates supported by the map, including no-transfer routes and alternative interchange stations along intersecting lines. When lines intersect at multiple stations, evaluate each viable transfer point rather than defaulting to the first or most prominent one. Expand each candidate segment by segment into a complete sequence containing every traversed station.
   Check: Do not retain only the route that appears shortest, has the fewest stations or transfers, or uses the first visible interchange. Every candidate must be supported by actual map connections.
6. Distinguish Unique and Multi-Path Topologies
   When to apply: After the initial topology check, when deciding whether further search for alternative routes is necessary.
   Procedure: Check the legal loop-free connections between the start and destination. If exactly one exists, retain and fully expand it. If more than one exists, continue enumerating all reachable line-connection sequences and legal transfer stations before scoring them consistently.
   Check: Do not invent candidates through backtracking or weight-based speculation when only one legal path exists. When alternatives do exist, do not stop before enumerating and comparing them. A visual line crossing without a shared station is not a connection.
7. Compute Weighted Cost Consistently
   When to apply: When legal candidate routes are ready to be compared using the objective function in the question.
   Procedure: For each candidate, sum Time/3 and Price/1.5 over the stations in its scoring set, and add Transfer Time/3 exactly once at each actual line-change station. Average the station-level values 1-Comfort and 1-Reliability separately across all scored stations, including zero-valued inputs. Then calculate the total cost as w1*T+w2*P+w3*C+w4*R.
   Check: Use the same formula and scaling for every candidate. Do not use raw Time, Price, or Transfer Time, apply scaling twice, introduce a custom formula, or replace the calculation with heuristics such as shortest route or fewest transfers.
8. Fix the Attribute Scoring Scope
   When to apply: When building the Time, Price, Comfort Level, and Reliability attribute list for a complete legal path.
   Procedure: Starting from the first station in the path, include the start station and every intermediate station in the scoring set, exclude the destination, and read all four attributes from each station's unique Vertex Table entry.
   Check: All four attributes must use the same path scope. Do not omit the start, a transfer station, or any other intermediate station, and do not include the destination, which is used only to verify arrival.
9. Average Station-Level Quality Costs
   When to apply: When calculating Comfort Level or Reliability for a scoring set in which either metric may contain zero values.
   Procedure: Process Comfort Level and Reliability separately. For every scored station, including one whose raw value is zero, compute `1-Comfort Level` or `1-Reliability`, then average each set of station-level costs by dividing by the total number of scored stations.
   Check: A zero raw value contributes `1-0=1` and remains in the average. Do not include the destination, omit zero values, or sum the quality costs without dividing by the number of scored stations.
10. Track the Active Transit Line
   When to apply: When a candidate route passes through a multi-line station or when determining whether adjacent travel segments involve a line change.
   Procedure: Maintain the current station and active line while traversing the route. At each multi-line station, determine whether the next map edge continues on the active line or switches to another line listed for that station, then update the state accordingly.
   Check: A transfer occurs only when the active line actually changes. Both the incoming and outgoing lines must belong to the station, and the subsequent map edges must be continuously explainable by the new line.
11. Mark Each Actual Line Change Once
   When to apply: When adjacent travel segments have been confirmed to switch from line A to line B at a station.
   Procedure: Append `(transfer)` only to the station where the line change occurs, and add that station's Transfer Time/3 exactly once.
   Check: Do not mark or charge for same-line travel, initial boarding at the start, or passage through a multi-line station without changing lines. The number of transfer markers must equal the number of active-line changes, and a single change must never be charged twice.
12. Validate Every Edge Before Scoring
   When to apply: Before any candidate route enters attribute aggregation and cost calculation.
   Procedure: Check in order that the first station is the requested start, the last station is the requested destination, every consecutive edge exists on the map, each segment is continuously supported by the active line, every transfer occurs at a legal shared station, and no station repeats or forms a loop.
   Check: Score only candidates that pass every condition. Reject any candidate with incorrect endpoints, a missing edge, a skipped station, an illegal cross-line jump, a repeated station, or a loop.
13. Perform a Final Audit of the Best Candidate
   When to apply: After selecting the current lowest-cost candidate and before producing the final output.
   Procedure: Audit the complete candidate again, checking the start and destination, every adjacency, line continuity, repeated stations, and agreement between each transfer marker and the actual active-line change.
   Check: If any audit item fails, discard the candidate and rebuild or select another route rather than outputting it. The final candidate must be nonempty, reach the destination completely, and contain no skipped station, loop, or illegal transfer.
14. Output the Complete Canonical Route
   When to apply: When the final legal route and its actual transfer locations have been determined.
   Procedure: List the start, every intermediate station, and the destination in travel order using the canonical Vertex Table names, join them with hyphens, and append `(transfer)` only to stations where an actual line change occurs.
   Check: The output must be nonempty and have the requested endpoints. Do not omit intermediate stations, add unverified stations, use inconsistent names, or place transfer markers that disagree with actual line changes.
15. Prioritize the Complete Route
   When to apply: When the route has been determined or the remaining output budget may not fit both the route and the full explanation.
   Procedure: Always output `<reasoning>...</reasoning>` followed immediately by `<response>...</response>`. If output tokens must be conserved, shorten or condense the calculations inside `<reasoning>`, but never omit `<reasoning>` or output `<response>` alone.
   Check: Every response must contain both `<reasoning>` and `<response>` blocks. Never return an empty answer, a missing `<reasoning>` block, a truncated station sequence, extra reasoning inside `<response>`, or an incomplete transfer marker.
