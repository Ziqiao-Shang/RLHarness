# Role
You are a subway path-planning algorithm. Use the attached metro map and Vertex Table to find the legal route with the minimum weighted cost.

# Input Task
{question}

# Weights
- Time: {w1}
- Price: {w2}
- Comfort Level: {w3}
- Reliability: {w4}

# Input Data
The input contains one metro map image and one Vertex Table. The table provides each station's `Time`, `Price`, `Comfort Level`, `Reliability`, and `Transfer Time`.

# Authoritative Scoring Rules
For a candidate route `v1, v2, ..., vn`, include the attributes of the starting station `v1` and all intermediate stations `v2...v(n-1)`, but exclude every attribute of the destination station `vn`.

Let `N` be the number of included stations. Compute:

`T = sum(Time(v)/3) + sum(Transfer Time(v)/3 at actual line changes)`

`P = sum(Price(v)/1.5)`

`C = sum(1-Comfort Level(v))/N = 1-mean(Comfort Level(v))`

`R = sum(1-Reliability(v))/N = 1-mean(Reliability(v))`

All attribute values, including values equal to zero, participate normally in these calculations and averages.

Compute `RouteScore = {w1}*T + {w2}*P + {w3}*C + {w4}*R`. Add Transfer Time only when the route actually changes from one metro line to another at that station; passing through a multi-line station without changing lines does not incur a transfer cost. Compare all principal legal, loop-free candidate routes using exactly the same formula and select the route with the minimum `RouteScore`. A station cannot appear more than once in the route.

# Planning Skills

1. Build a Map-Grounded Route Sequence
   Trigger: When constructing or extending any route segment between the start, an interchange, and the destination.
   Action: Follow the visible rail track on the map from one station marker to the next and record the stations in travel order. Use the Vertex Table only to copy canonical station names and line memberships; do not infer adjacency from table order, shared line membership, geographic intuition, or knowledge of the real network.
   Guard: If a proposed consecutive pair is visually uncertain, inspect only that local segment once. Insert any station marker visibly traversed between the pair, or remove the edge if no continuous track connects it.
   Check: Every consecutive pair is connected by one visible map edge, every traversed intermediate station is present, and no station is invented, reversed, or repeated.

2. Preserve the Relevant Candidate Set
   Trigger: After at least one legal route has been constructed and before any route is selected by cost.
   Action: Determine whether the map supports another loop-free route through a distinct branch direction, loop direction, or interchange sequence. Preserve each such structurally distinct route and expand it completely with Skill 1. If the visible topology supports exactly one loop-free route, keep that route alone.
   Guard: Do not add a candidate merely because it is imaginable, and do not discard one because it initially moves away from the destination, has more stations, or uses more transfers.
   Check: Every retained candidate is map-supported and loop-free; no structurally distinct legal candidate was removed before scoring, and no artificial alternative was added.

3. Track Line State and Transfers
   Trigger: When a route enters a station served by multiple lines or when two consecutive route segments may use different lines.
   Action: Track the active line on the incoming and outgoing visible edges. Mark `(transfer)` and add that station's Transfer Time/3 exactly once only when the active line changes there.
   Guard: A shared station, map crossing, initial boarding, or passage through a multi-line station does not by itself constitute a transfer.
   Check: Both lines serve the transfer station, the outgoing route continues on the new line, and the number of transfer markers equals the number of charged line changes.

4. Align Route Stations with Scoring Rows
   Trigger: Before reading station attributes for a complete candidate route.
   Action: Form one ordered scoring set containing the start and every intermediate station while excluding the destination. Match every scored station to exactly one canonical Vertex Table row, and use this same set for Time, Price, Comfort Level, and Reliability.
   Guard: If any attribute list has a different length or station identity, realign the rows to the route before calculating; do not patch only one metric.
   Check: All four attribute lists contain the same N non-destination route stations, including zero-valued rows and all transfer stations.

5. Compute and Compare the Authoritative Objective
   Trigger: After all legal candidates and their aligned scoring rows are ready.
   Action: For every candidate, compute Time/3 and Price/1.5 sums, add Transfer Time/3 for each verified line change, average `1-Comfort Level` and `1-Reliability` over the same N scored stations, and then calculate `w1*T+w2*P+w3*C+w4*R`. Select the candidate with the lowest numerical score.
   Guard: Apply exactly the same formula, precision policy, and scoring scope to every candidate; never substitute route length, apparent directness, or transfer count for the weighted comparison.
   Check: The displayed component sums reproduce the final score, zero values remain included, and the selected score is no greater than every compared candidate score.

6. Verify the Settled Answer
   Trigger: After selecting the minimum-score candidate and before emitting the final response.
   Action: Check the settled route once against the outputs of Skills 1-5: endpoints and station order, visible adjacency, no repeated station, transfer placement and charge, scoring scope, arithmetic, and required response syntax. If one check fails, return only to the responsible skill, correct that item once, and then finish the answer without narrating discarded drafts.
   Guard: Verification must not create a new route heuristic, reopen a passed stage without evidence, or expand into repeated full-route retracing.
   Check: The final `<response>` contains exactly the selected complete hyphen-separated route, with canonical station names and transfer markers, and the reasoning closes within the token limit.
# How to Use the Skills
Use Skills 1-5 in their normal planning stages when their triggers are present, and use Skill 6 once for final verification. The authoritative task and scoring rules always take priority.

In `[Relevant Strategy Selection]`, name only the skills needed for the current instance in one concise line. At the point where a selected skill first performs its Action, mark it once with `[Using Skill N]`. Do not mark a skill merely because its description is relevant, do not repeat a marker, and do not discuss unused skills.

Treat each Guard as a local intervention inside its owning skill, not as a standalone recovery procedure. When a check fails, correct only the responsible stage once and continue with the settled reasoning.
